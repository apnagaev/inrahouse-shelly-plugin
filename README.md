# Shelly 1 для intraHouse v5

Плагин управляет реле Shelly 1 первого поколения через локальный HTTP API. Каждый экземпляр обслуживает одно реле. Достаточно доступа из сети сервера intraHouse к адресу Shelly. Для Plus 1 и других устройств с RPC API нужен отдельный драйвер.

## Установка

1. Скачайте [ZIP исходников ветки main](https://github.com/apnagaev/inrahouse-shelly-plugin/archive/refs/heads/main.zip). В Project Manager откройте **Плагины → Import**, загрузите ZIP и обновите страницу. При ручной установке распакуйте содержимое архива в каталог `plugins/shellyrelay` на сервере. Файл `manifest.json` должен лежать в корне этого каталога.
2. Добавьте экземпляр **Shelly 1** (идентификатор `shellyrelay`). Укажите IP или DNS-имя. Можно задать порт. Если включена HTTP-аутентификация Shelly, заполните логин и пароль в параметрах экземпляра.
3. Добавьте **Набор каналов Shelly 1** и запустите экземпляр. Интервал опроса по умолчанию составляет 5 секунд, тайм-аут запроса — 2500 мс.
4. Проверьте, что канал `online` равен 1 и что `state` отражает фактическое состояние. Затем проверьте запись на выбранном реле.

| Канал | Доступ | Значение |
| --- | --- | --- |
| `online` | Чтение | 1 после успешного запроса, 0 при ошибке. |
| `state` | Чтение и запись | 0 = выключено, 1 = включено. |
| `timeOff` | Чтение и запись | Настроенный в реле таймер автоотключения в секундах. Ноль отключает таймер. |
| `buttontype` | Чтение и запись | Режим входа SW. Допустимы `momentary`, `toggle`, `edge`, `detached`, `action`, `momentary_on_release`. |

Плагин публикует фактическое значение из ответа Shelly. При потере связи последние известные значения сохраняются, а `online` становится равен 0. При старте плагин читает состояние и настройки. Команды записи поступают от intraHouse.

## Обновление с 5.2.0

В 5.2.1 внутренний идентификатор изменён с `shelly1` на `shellyrelay`: intraHouse использует цифровой суффикс для номера экземпляра. Сначала импортируйте ZIP с новым идентификатором. Затем перенесите параметры и привязки каналов на новый экземпляр. Для проекта intral24 эту замену выполняет отдельный коммит проекта. Если переносите вручную, остановите старый экземпляр перед переключением привязок.

## Тип устройства и диалог

В ZIP исходников шаблон диалога и установщик лежат в `extras/`, как у GitSync. Диалог показывает связь и состояние реле, включает и выключает его, сохраняет таймер в секундах и позволяет выбрать режим входа SW.

Для нового устройства остановите intraHouse и запустите `node extras/install.js /путь/к/проекту`. После запуска intraHouse создайте устройство типа **Shelly 1 · Реле** и привяжите набор каналов Shelly 1.

1. Сохраните резервную копию файлового проекта. У существующего устройства должны быть стандартные команды `on` и `off` и свойства `state`, `online`, `timeOff` и `buttontype`, привязанные к одноимённым каналам плагина. Для диалога утюга добавьте свойство `online`, если есть только `ping`.
2. Остановите intraHouse и выполните от имени владельца проекта:

   ```sh
   node extras/install.js /путь/к/проекту d0004
   ```

   Подставьте внутренний ID своего устройства. Установщик выведет ID диалога. Повтор той же команды проверяет уже установленный диалог и сохраняет его.
3. Запустите intraHouse и назначьте плитке действие **Показать диалог** с выведенным ID. Импорт ZIP устанавливает сам плагин. Установщик добавляет тип и, при передаче ID устройства, диалог. Существующие устройства сохраняют свои типы.

При выключении реле из веб-интерфейса Shelly intraHouse увидит изменение при следующем успешном опросе. При интервале 5 секунд это обычно занимает до 5 секунд плюс время HTTP-запроса.

## Переход в intral24

Создайте экземпляр для каждого выбранного реле. Переиспользуйте существующий ID устройства и привязки свойств. Снимите старые привязки соответствующих каналов MQTT/HTTP перед добавлением новых, чтобы у каждого свойства был один источник состояния и один исполнитель записи.

| Устройство проекта | Свойства для привязки |
| --- | --- |
| Утюг `R_001` (`d0004`) | `state`, `timeOff`, `buttontype`. Канал `online` можно привязать к существующему `ping` после снятия старой привязки. |
| `polo_aircon`, `FAN_001` (`d0038`) | `state`. Связанный датчик `DI_012` можно оставить на ICMP или отдельно перевести на `online` для контроля доступности HTTP API. |
| Подсветка санузла `H_015` (`d0172`) | `state`. Перед переносом проверьте, что контроллер отвечает через API Gen1. |

В реестре сценариев `shelly_timeoff` запускается по `shelly.timeOff`, а `shelly_auto` — по `shelly.auto`. Свойства `auto`, `timeOffmin` и `tmptimeOff` относятся к логике проекта. Оставьте их в существующем устройстве и проверьте оба сценария после смены привязок. Для проверки утюга сначала используйте отключённую нагрузку и проверьте положительный таймер автоотключения на самом Shelly.
